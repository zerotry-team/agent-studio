# Agent Builder × ファクタリング審査 3分デモ台本

## 最初の一言

> Agent Studioは、質問へ答えるAIではありません。会社の仕事をするAIを、自然な日本語から作って配備する「AIを作るAI」です。

この一文を言ってから実演を始めます。

## 0:00〜0:25　何を作ったのか

### 見せる画面

ClearFactorの申込画面。

### 話す内容

> 今から、ファクタリングの申込から事前審査までを通します。
>
> このClearFactorは、お客様が使う申込SaaSです。Agent Studioの中に作った画面ではありません。Agent Studioは、このサービスの裏側で働く審査Agentを作り、動かす基盤です。

### 必ず伝えること

- 表側は別SaaS、裏側がAgent Studio
- すべて架空データ
- 正式契約ではなく事前審査候補

## 0:25〜0:50　テストデータを見せる

### 指さす場所

- 請求書番号：`INV-2026-0104`
- 請求書額：4,300,000円
- 希望額：800,000円
- 通帳資料の参照番号：`statement-2026-04-09`

### 話す内容

> 430万円の請求書に対して、80万円の資金化を申し込みます。
>
> 通帳そのものは送りません。企業環境の中にある資料を、参照番号で指定します。

## 0:50〜1:10　ボタンを押す

### 操作

「無料で事前審査する」を押す。

### 話す内容

> いま、表示用のタイマーではなく、実際のWorkflow Runが始まりました。
>
> 裏では、申込DB、過去履歴、入金実績、通帳の集計結果、コンプライアンス情報を順番に確認しています。

## 1:10〜1:45　審査中に「安全性」を説明する

### 見せる画面

「申込受付」「請求・入金確認」「審査結果」の進捗。

### 話す内容

> AgentはDBへ自由なSQLを書けません。許可されたToolだけを使います。
>
> 通帳原本とSecretは、会社側のSelf-hosted Runtimeに残します。AIへ渡すのは「3か月継続」「名義一致」のような必要最小限の結果だけです。
>
> さらに、金融の判定をLLMの感覚に任せません。金額や履歴は`factoring-v2`という固定ルールで計算します。

## 1:45〜2:10　結果を見せる

### 指さす場所

- 「お申込みいただけます」
- 希望金額800,000円
- 結果「可」
- 社内記録「完了」
- 確認できた2つの理由

### 話す内容

> 結果は「可候補」です。
>
> 過去の相談履歴があり、希望額が100万円未満であること、3か月の継続入金があることを固定ルールで確認しました。
>
> 結果は社内DBへ1件だけ記録されています。同じ実行をやり直しても二重登録しません。

## 2:10〜2:35　Agent Studioの実行履歴を見せる

### 見せる画面

Agent Studioの実行履歴。Run IDは`674e402a-f279-4da8-a906-0276232e81e5`。

### 話す内容

> 表側のこの結果と、裏側のAgent StudioのRunが同じIDでつながっています。
>
> どのToolが、どの順番で、どのルールを使い、何を記録したかを後から追えます。
>
> 今回はデモ用の`safe_auto`設定で、架空データの社内承認だけ自動通過させました。外部SNS投稿は別権限なので実行していません。

## 2:35〜2:55　4時間の意味を説明する

### 話す内容

> 本来は、API、認証、DB接続、通帳処理、ルール、承認、二重登録防止、Worker、監査、配備を個別に作る必要があります。
>
> 今回はAgent Builderが、自然言語の依頼をTool、Connector、Workflow、Policyへ分け、約4時間でこの縦切りデモをPreview環境まで通しました。

## 2:55〜3:00　最後の一言

> AIに仕事を聞くのではなく、AIに「安全に働くAI」を作らせる。それがAgent Studioです。

ここで止めます。最後に機能一覧を追加しません。

## 審査員に「つまり何？」と聞かれたときの一文

> 日本語で仕事を説明すると、社内データへ安全につながり、決めた手順で実行し、結果と証拠を残すAI社員を作れるサービスです。

## よくある質問への短い回答

### 「これはただのチャットボットですか？」

> 違います。回答だけでなく、Tool実行、条件分岐、承認、DB記録、監査、配備まで扱います。

### 「AIが勝手に金融判断をしますか？」

> しません。LLMは整理と説明を担当し、金額や履歴の判定は固定ルールが担当します。

### 「通帳をAIへ送っていますか？」

> 原本は送りません。会社側のRuntimeで処理し、継続月数や名義一致だけを返します。

### 「4時間で本番完成ですか？」

> いいえ。4時間で作ったのは架空データの縦切りデモです。本番審査規程、実接続、セキュリティ審査、監視、Production承認は別途必要です。

### 「承認でデモが止まりませんか？」

> 通常デモは`safe_auto`で社内承認だけ自動通過します。手動確認へ切り替えられ、外部公開は別の権限です。
